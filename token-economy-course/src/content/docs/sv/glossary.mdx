## A–B

### Agentläge (Agent mode)

Ett av tre Copilot Chat-lägen. I Agent mode planerar, utför och itererar Copilot självständigt kring uppgifter i flera steg med hjälp av verktygsanrop. Det har den högsta tokenkostnaden per uppgift men är det mest kapabla läget.

### Agentisk loop (Agentic loop)

Den femstegscykel som agenter följer: Analyze → Plan → Execute → Test → Iterate. Varje cykel ökar den sammanlagda tokenkostnaden.

### Agentiskt arbetsflöde (Agentic workflow)

Ett strukturerat arbetssätt där AI-verktyg används inom tekniska discipliner som formella specifikationer, acceptanskriterier, säkerhetsgranskningar och kontinuerliga testcykler. Det står i kontrast till vibe coding.

### AI Credits

GitHub Copilots förbrukningsenhet för användningsbaserad debitering. Varje chatt-, agent- eller API-interaktion drar credits från en pott. Överanvändning debiteras med $0,01 per credit.

### Alltid-på-skatt (Always-on tax)

Tokenoverhead som betalas i varje förfrågan från filer som läses in utan villkor, till exempel `copilot-instructions.md`, `AGENTS.md` och öppna flikar. Att minska denna baslinje är den mest effektiva optimeringen.

### AGENTS.md

En beteendekontraktfil som definierar hur Copilot ska bete sig i agentläge. När den finns kan den läsas in som systemkontext för varje agentsteg. Den bör hållas slimmad (cirka 80 tokens) med regler för läge, omfattning och utdataformat.

### Frågeläge (Ask mode)

Ett chattbaserat Copilot-läge för frågor och förklaringar. Det kör inga verktyg och har den lägsta tokenkostnaden, ungefär 500 tokens per tur.

### Batchning av bakgrundsarbete (Background work batching)

En optimering i harnessen som köar kontexthämtning, embedding-beräkning och indexering i en enda batch under inaktiva perioder i stället för separata rundresor.

### BPE (Byte-Pair Encoding)

En tokeniseringsalgoritm som delar upp text i delordsenheter. Den påverkar hur effektivt olika språk tokeniseras; engelska är mer BPE-effektivt än svenska.

## C

### Cache-brytpunkt (Cache breakpoint)

En uttrycklig markör i Anthropics API som talar om vilka prefixdelar modellen ska cacha. Cacheträffar är ungefär 90 procent billigare än ny beräkning.

### Caveman-språk (Caveman-speak)

En teknik för promptkomprimering som tar bort artiklar, prepositioner och grammatik men behåller semantiska nyckelord. Oberoende tester visar ungefär 8,5 procents tokenbesparing.

### Kontextfönster (Context window)

Det maximala antal tokens som en modell kan bearbeta i en enda förfrågan, vanligtvis 128K–200K beroende på modell. När det fylls kan modellen i praktiken glömma tidigare innehåll.

### Kontinuerlig batchning (Continuous batching)

Att gruppera flera inferensförfrågningar i batcher om 64–128 för att maximera GPU-utnyttjandet. Det minskar kostnaden per token dramatiskt jämfört med inferens för en enda förfrågan.

### Anpassad agent (Custom agent)

En användardefinierad Copilot-agent med avgränsad kontext och verktyg. Den är mer effektiv än `@workspace` eftersom den läser in färre verktygsdefinitioner och ett mindre filträd.

## E–F

### Redigeringsläge (Edit mode)

Copilot-läge för redigering av en enda fil. Det har måttlig tokenkostnad, ungefär 1–2K tokens per tur, och använder inga verktygsslingor.

### Effektiva tokens (Effective Tokens, ET)

En formel, `m × (1.0×I + 0.1×C + 4.0×O)`, som normaliserar kostnader mellan input-, cache- och outputtokens. Den är mer meningsfull för jämförelser än ett rått tokenantal.

### Embeddingvektorer (Embedding vectors)

Numeriska representationer av text som används för semantisk sökning. Tool Search använder embeddings för att hitta relevanta verktyg för varje förfrågan.

## G–H

### Limkod (Glue code)

Integrationskod som kopplar samman befintliga system, bibliotek eller tjänster. Den lämpar sig väl för agentisk kodning eftersom den följer etablerade mönster.

### GPU-utnyttjandegrad (GPU utilization rate)

Den procentandel av tiden som en GPU aktivt beräknar. Under ungefär 72 procents utnyttjande är serverless-infrastruktur billigare än dedikerad hårdvara.

### Skyddsräcken (Guardrails)

Metoder som hindrar AI-genererad kod från att samla på sig teknisk skuld, inklusive lätta specifikationer, TDD, arkitektonisk översyn och uttryckliga stoppvillkor.

### Harness

Det agentiska ramverket i VS Code som sätter ihop kontext, hanterar verktyg och dirigerar förfrågningar innan de når modellleverantören.

## I–L

### Avsiktskommentar (Intent comment)

En `// AI:`-kommentar i källkod som fångar utvecklarens avsikt så att modellen kan läsa den tillsammans med koden. Den kan spara in en full förklaring i chatten.

### K/V-cache (Key/Value cache)

Modellens interna tillstånd som beräknas från promptprefixet. Cachade K/V-tensorer kan återanvändas när prefixet förblir identiskt, vilket gör senare turer dramatiskt billigare.

### Lazy loading (instructions)

Att använda `.prompt.md`-filer som laddas vid behov genom `#file:`-referenser i stället för att lägga all vägledning i den alltid inlästa `copilot-instructions.md`.

### .prompt.md-filer

Domänspecifika vägledningsfiler som laddas vid behov via `#file:`-referenser. Där lagrar du arkitekturspecifikationer, konventioner och kända problem utan att betala alltid-på-skatten i varje förfrågan.

## M

### MCP (Model Context Protocol)

Ett öppet protokoll som låter Copilot använda externa verktyg — som databaser, GitHub eller filsystem — via standardiserade servrar. Varje server registrerar verktyg med namn, beskrivning och parameterschema i agentens verktygsregister. Fler servrar = fler verktygsdefinitioner i kontexten, vilket kan göra agenten långsammare. Därför lönar det sig att bara ha aktiva servrar du faktiskt använder.

### Metaprompt (Meta-prompt)

En prompt som styr utdataformatet i stället för att begära innehåll. Exempel är ”Svara med högst tre punktlistor” och ”Bara kod, ingen förklaring”.

### Modellmultiplikator (Model multiplier, m)

Ett värde i formeln Effective Tokens som normaliserar prisskillnader när du byter mellan modeller med olika kostnad per token.

## O

### Optimeringsloop (Optimization loop)

Cykeln Mät baslinje → Ändra en variabel → Upprepa uppgiften → Jämför → Behåll den bättre konfigurationen. Det är kursens kärnmetodik.

### Outputkomprimering (Output compression)

En optimering i harnessen som normaliserar blanksteg, tar bort radnummer och strukturerar utförlig output. Den sparar i genomsnitt ungefär 5,5 procent av outputtokens.

## P

### Prefixcachning (Prefix caching)

När början, eller prefixet, i flera förfrågningar är identiskt återanvänder leverantören beräknat tillstånd i stället för att räkna om det. Cacheträffar är ungefär 90 procent billigare än nya tokens.

### Promptprefix (Prompt prefix)

Den återkommande början av varje förfrågan i en session: systeminstruktioner, verktygsdefinitioner och konversationshistorik. Att hålla den stabil är den största hävstången för tokenoptimering.

## Q–S

### Kvalitetströskel (Quality threshold)

Fördefinierade framgångskriterier, till exempel passerade tester, ändrade obligatoriska filer, inga kritiska fel och högst en liten korrigering. De används för att bedöma om en kostnadsoptimering bevarade resultatkvaliteten.

### Dedikerad GPU (Dedicated GPU)

Provisionerad GPU-hårdvara för modellinferens som debiteras per timme oavsett användning. Den blir kostnadseffektiv först över ungefär 72 procents varaktigt utnyttjande. Den står i kontrast till serverless-infrastruktur med betalning per användning.

### Serverless (GPU)

GPU-infrastruktur med betalning per användning där du debiteras per token. Den passar bäst för burstiga, asynkrona agentsessioner och står i kontrast till dedikerade GPU-instanser.

### Systemprompt (System prompt)

Instruktioner på modellnivå som definierar modellens roll, förmågor och beteende. De skickas med varje förfrågan och omfattar vanligtvis ungefär 500 tokens. De är en del av den fasta baskostnaden.

### Stoppvillkor (Stop condition)

En uttrycklig gräns i agentinstruktioner som talar om när agenten ska stanna, till exempel ”Om testerna passerar, stanna och invänta granskning.” Det förhindrar kostsamma oändliga iterationsloopar.

## T

### Token

Den grundläggande textenhet som en språkmodell bearbetar. En token motsvarar ungefär tre fjärdedelar av ett engelskt ord. Modeller prissätts per miljon tokens (input och output). Tokens kan vara input (din prompt), output (modellens svar) eller cacheade (återanvända från tidigare förfrågningar).

### Teknisk skuld (Technical debt)

Den underförstådda kostnaden för omarbete som uppstår när snabba lösningar väljs framför robusta. AI-genererad kod kan bygga upp skuld genom duplicerad logik, oavsiktlig arkitektur och uppsvällda funktioner.

### Thinking effort

En VS Code-inställning som styr hur mycket resonemang en modell använder per förfrågan. Högre nivå innebär fler thinking tokens, högre latens och fler credits, så använd standardvärden för rutinuppgifter.

### Tokeniserare (Tokenizer)

Algoritmen som delar upp text i tokens före modellbearbetning. Olika modeller använder olika tokeniserare, och effektiviteten varierar mellan språk.

### Verktygsregister (Tool Registry)

Den alltid närvarande katalogen över verktygsnamn och korta beskrivningar. Med Tool Search laddas fullständiga verktygsscheman vid behov i stället för att permanent uppta kontext.

### Tool Search

En optimering i VS Code, tillgänglig från mitten av 2025 och framåt, som bara laddar fullständiga verktygsscheman när modellen begär dem i stället för att läsa in alla verktygsdefinitioner i varje steg. Den minskar verktygsoverhead med ungefär 60–75 procent.

### TTFT (Time-To-First-Token)

Latensen mellan att en förfrågan skickas och att den första svarstoken tas emot. WebSocket-anslutningar minskade median-TTFT med ungefär 19 procent under 2026.

### TLS (Transport Layer Security)

Ett kryptografiskt protokoll som skyddar HTTPS-anslutningar. WebSocket-användning eliminerar upprepade TLS-handskakningar och minskar overhead per tur.

## U–W

### UBB (Usage-Based Billing)

GitHub Copilots debiteringsmodell sedan juni 2026. Du betalar för det du använder, mätt i förbrukade tokens, i stället för en fast avgift per plats.


### Vibe coding

En utvecklingsstil där utvecklaren beskriver intentionen och låter AI generera kod med minimal översyn. Den passar bäst för utforskning och prototyper men är riskabel för produktionskritisk kod.

### Verifiering kontra upptäckt (Verification vs Discovery)

Ett ramverk för att välja mellan agentiska arbetsflöden och vibe coding. Använd verifiering för affärskritisk kod med skyddsräcken och upptäckt för prototyper och experiment.
