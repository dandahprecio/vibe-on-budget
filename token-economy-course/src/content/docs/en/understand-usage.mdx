## The question this module answers

What is actually being used when you ask an AI model for help?

This is the first part of the course, so there is no previous section to connect to. The goal is to create a simple mental model that we can use throughout the rest of the course: assess the whole correctly completed task, not just the length of your first prompt or how quickly the first answer arrived.

## Explanation

We will introduce the terms in small steps.

A **prompt** is what you ask the model to do, for example: “Add a test for the function that sorts the customer list.” A **model** is the AI service that interprets the prompt and formulates a response. Different models can have different strengths, workflows, and usage levels.

To process text, it is split into smaller parts called [**tokens**](/vibe-on-budget/en/glossary). A token is not the same as a word: a word, part of a word, a space, or punctuation can each contribute differently. You do not need to count tokens manually to understand the principle. The important point is that both your prompt and the material around it can contribute to the amount processed.

The material sent to the model is called **input**. It can include the prompt, relevant parts of a file, previous messages, or instructions that apply to the workspace. What the model sends back is called **output**. It can be an explanation, code, a question for you, or a suggestion for the next step.

Together, the material the model can use forms the task's [**context**](/vibe-on-budget/en/glossary). Context is therefore larger than the prompt itself. A short question in a large or long session can still carry a lot of context.

Consider a small task in a project. You write a short prompt: “Fix this test.” To do a good job, the workflow may still include several requests:

1. The model investigates the test and the code it tests.
2. You answer a follow-up question or clarify the intended behavior.
3. The model suggests or makes a change.
4. A test reveals a new error, so the model needs to read the error and correct the change.
5. The model summarizes what changed and what was checked.

The short first prompt does not describe the whole job. Each step can use input and create output. That is why a correctly completed task can use more than the first line suggests — but can also be more valuable than a quick, incorrect answer.

In this context, **credits** are a measure of usage or consumption. They should be distinguished from the subscription fee. The subscription is the cost of the plan itself; included credits describe how much usage the plan covers. If a service shows additional charges, they depend on the service's current terms. Check the view and plan that apply to your environment instead of assuming that all users have the same limits.

In some workflows, recurring material can be reused through a **cache**. Put simply, the system may not need to process exactly the same part from scratch again. Caching is a possible reuse, not a saving you can count on for every request. What gets reused depends on the service and workflow.

## Practical choices and limitations

When you compare two workflows, look at the entire task:

- **Result quality:** Did the result meet the requirements? Was the change verified? Has it been reviewed?
- **Effort:** How many requests, credits, minutes, corrections, and manual retries were required?
- **Conditions:** Did the tasks use the same starting state, context, and roughly the same requirements?

A shorter prompt can be better when it is clear and provides the right material. A longer prompt can be more efficient when it prevents misunderstandings and rework. There is no universal percentage that determines what is “cheap” or “efficient.”

Visible usage also has limits. Not every environment shows the same details, and a local sense of speed is not a reliable measure of credits. If a usage view exists, use it as an observation about your environment — not as a promise about another plan, model, or session.

## Optional exercise in your own project

**Identify where your usage is shown, if the feature exists.**

Do this:

1. Open the usage or account view for your AI service.
2. Note which details are actually shown, such as credits, messages, or model.
3. Mark anything that is not shown. Write “not available” instead of estimating actual credits.
4. Do not compare results yet. The goal is only to know which observations you can make later.

## Question: Two questions of the same length cost different amounts. How can that happen?

<details>
<summary>Show answer</summary>

Prompt length does not tell you which **context**, **model**, or amount of follow-up work was used. One question may be sent with more file content and a longer history. It may also use a different model, produce a longer answer, or lead to several follow-up questions and corrections. You therefore need to assess the whole correctly completed task, not just the number of characters in the first question.

</details>

## Summary

A prompt is your instruction, the model processes it, tokens describe its smaller text units, input is what is sent in, and output is what comes back. Context includes the prompt and other relevant material around it. A task can consist of several requests, and credits describe usage while the subscription fee describes the plan. A cache can sometimes reuse material, but it is not guaranteed.

The next section moves from concepts to action: you will try a small, controlled task and learn what to check before and after a change. This lets you connect quality, time, and actual effort instead of looking only at prompt length.
